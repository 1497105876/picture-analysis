## 1. 模拟用户旅程（15 步，逐条实录）

### 第 1 步：打开首页
`GET /` → 200，界面正常渲染。侧栏分「浏览 / 整理 / 运维」三组，`分类` 与 `运维` 带「新」标记。顶栏有面包屑、搜索框、四个图标（处理器＝后端连接、铃铛＝通知、调色板＝外观）。

✅ 结论：外壳成型，观感比旧版利落。

### 第 2 步：图库首屏
已登记目录 1 个（`C:\Users\highness\Pictures\3D`），图片 0 张。

⚠️ **发现**：图片列表接口在**库里 0 张图**的情况下**耗时 2126 ms**（`timings.total_ms = 2126.41`）。3 张图时是 3.92 ms。首屏慢得不像话，而且和图片数量无关——这是空库时的一次性开销，具体原因待查（疑似向量/嵌入客户端初始化或 embedding 表扫描）。

### 第 3 步：登记目录（两阶段向导）
估算 0.01 s 返回：`3 个文件 / 344 KB / 预计 2700 tokens / 0.5 分钟 / 在日预算内`；第二步确认登记 + 扫描 0.90 s，返回 `added: 3`。

✅ 结论：**这是全产品体验最好的一处**。先估数再落库、明确告诉你「phase-1 不调用 AI」，对怕花钱的人非常友好。

### 第 4 步：等识图，看任务页
扫描完成后 3 张图立即排队识图，任务页能看到 `analyze` 与 `embed` 两类任务。

❌ **发现（严重）**：`embed` 任务**全部失败并已耗尽重试**，错误原文：
> AI 服务拒绝请求（400）：This model does not appear to be an embedding model by default. Please add `--is-embedding`

你配的档案 `ag`（`https://apihub.agnes-ai.com/v1`）里，**嵌入模型填的是 `agnes-3.0-flash`——一个识图模型，不是嵌入模型**。后果：
- 所有向量检索永远不可用 → 检索页**永远显示「已降级」**
- 以图搜图（详情抽屉里的「相似图片」）永远空
- 智能相册的语义能力打折

⚠️ 这是本次走查**最有价值的一条**：界面上看不出病根。任务页只告诉你「embed 失败」，检索页只告诉你「已降级」，但没有任何一处提示「你该去设置里换一个嵌入模型」。

### 第 5 步：仪表盘
统计卡、分类分布、按月分布、目录占用都正常。识图成功 1 张、失败 2 张。

⚠️ **发现（布局 bug）**：整个页面的内容宽度只有 **约 400px**，居中显示，右侧大片空白（见 `_shots/dashboard.png`）。原因是我在 `.app-main` 上同时写了 `max-width` 和 `margin: 0 auto`——在 flex 纵向容器里，交叉轴上的 auto 外边距会让元素**收缩成内容宽度**而不是撑满。所以「页面窄不窄」取决于该页内容的最小宽度：图库（图片网格最小 208px）看起来正常，仪表盘/分类/回收站这类宽内容就明显发窄居中。
**影响面**：所有内容较窄的页面，观感明显不对。

### 第 6 步：筛选用图
筛选条（目录 / 分类 / 状态 / 评分 / 收藏 / 标签 / 排序 / 升降序 / 视图切换 / 批量）齐全，响应正常。

❌ **发现（功能 bug）**：「全部分类」下拉**永远是空的**。因为 `catalog.categories` 被赋成了 `{items: [...]}` 这个对象而不是数组（和第 7 步同一个根因）。

### 第 7 步：打开运维页
❌ **发现（P0，整站白屏）**：`/ops` **完全空白**，连侧栏和顶栏都没有。控制台报错：
```
TypeError: qe.items.reduce is not a function
TypeError: m.items.map is not a function
```
根因：通知接口 `/api/notices` 返回的是 `{"items": [...]}`，我在 `notices.js` 里把整个响应体当数组存了（`notices.items = data`，而应该是 `data.items`）。于是：
- 顶栏 `unreadCount` 计算抛错 → **App 外壳渲染失败 → 整站白屏**
- 运维页 `filtered` / `kinds` 抛错 → 该页必然白屏

⚠️ 严重性说明：这不是「某个页面坏了」，而是**任何页面都可能白屏**——只要通知数据到达。我截的 6 张图里 gallery / search / dashboard / settings / categories / jobs 都正常，只有 ops 白屏，是因为截图时机的先后差异（数据到达前渲染的页面侥幸活了下来）。**你用的时候大概率先看到正常的图库，点几下之后就白屏了**——这也解释了你说的"还是有一些问题"。

### 建议明确不做（避免过度建设）

13. 幻灯片轮播、图片旋转、目录层级树：这三个要动后端 + 大改前端，收益对你的实际用法（Agent 检索基建 + 本地审核）有限，可以先放着。
