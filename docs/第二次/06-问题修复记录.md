## 一、致命 3 条（会把人劝退的）

### 1. 整站白屏
**症状**：点任何页面都可能全白，之后点什么都没反应，只能刷新。

**根因**：`/api/notices` 返回 `{items:[...]}`，而 `notices.js` 把整个响应体当数组存了。
顶栏的未读角标要 `reduce` 它 → App 外壳渲染抛错 → 整个应用死掉。

**修法**（`app/notices.js`）：
```js
const data = await safe(() => api.notices(limit), null);
notices.items = Array.isArray(data?.items) ? data.items : [];   // 取对层级 + 兜底
```

### 2. 分类下拉全空
**症状**：图库/抽屉的「分类」下拉是空的，分类页显示「还没有分类」，相册只能手写 JSON。

**根因**：和上一条同一个错误——`catalog.js` 里 `categories` / `customFields` 被赋成了 `{items:[...]}` 对象。
更隐蔽的是：`v-for` 遍历对象会**遍历出键名**，所以下拉里出现过一个内容为 `items` 的诡异选项。

**修法**（`app/catalog.js`）：同样取 `data.items` 并做 `Array.isArray` 兜底。

### 3. 没配 AI 时界面一声不吭
**症状**：照片入库后一直「排队中」，用户不知道为什么不识别、是坏了还是卡住了。

**修法**：新增队列状态单例 + 图库页顶部横幅。

- `app/notices.js` 新增 `queue`（是否有暂停任务、暂停原因），由 App 的轮询统一刷新（不额外发请求）
- `pages/Gallery.vue` 新增 `aiHint`：库里有未识别的图、且满足以下之一时出横幅：
  - 没有任何服务档案 → 「N 张已入库，但还没配置 AI 服务，识别不会开始」+「去配置档案」
  - 有暂停中的任务 → 「识别队列已暂停：<原因>」+「看任务队列」

### 时间口径（10，同时也修了 04 文档的 C3）

后端原本两种口径混用：`created_at` 是真 UTC，而 `last_scanned_at` / 回收站 `deleted_at` 用
`time.strftime` 写**本地时间却标了 `+00:00`**。前端只做字符串截取，于是前者显示早 8 小时、后者显示正确，
同一屏上两个口径。

**修法**（前后端一起改，这是唯一能根治的方式）：

- 后端：`ingest.py` 的 `last_scanned_at`、`manage_svc.py` 的 `deleted_at` 改走 `now_iso()`（真 UTC）
  - 顺带删除两个文件里不再使用的 `strftime` 调用点（文件名时间戳保留本地时间，那个不影响显示）
- 前端：`format.js` 的 `datetime()` 改成交给 `new Date()` 解析：
  - 带 `Z` / `+00:00` → 按 UTC 解析并转本地
  - 不带时区 → 按本地时间原样显示（兼容极少数历史数据）

> **注意**：修复前写入的历史数据（那个「本地时间冒充 UTC」的值）会显示成偏后 8 小时。
> 你库里只有 `Pictures\3D` 的 `last_scanned_at` 一条，**重新扫描一次目录就会写成正确值**。
