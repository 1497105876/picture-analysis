# 07 · 用户场景全量复盘（第二轮）

> 起因：爹删了一张图，问我「想恢复怎么办」——答案当时是「恢复不了」。
> 「只删索引」写了一条谁也看不见的墓碑，回收站里没有、界面上没有入口、重扫还会跳过它。
> 这不是一个 bug，是我把「删除」当成了终点，没想到删除之后还有人。
>
> 所以这一次不是修一条，是把一条数据从进来到离开的全过程重新走一遍，逐个问：
> **用户在这一步做错了/后悔了/环境变了，他还能回头吗？**
> 下面每一条都是照着代码和真实跑出来的行为写的，不是设想。

---

## 一、复盘视角：一条数据的完整寿命

```
选目录 → 扫描入库 → 识别 → 打标分类 → 日常查看 → 反复修改
   ↓                                                    ↓
 环境变了（改名/挪走/换盘/盘掉线）              删索引 / 删源文件 / 隐藏
   ↓                                                    ↓
 索引和磁盘对不上                                还能回去吗？← 本轮重点
```

判断「这一环有没有坑」只用一个问题：**用户在这一步可不可以后悔。**
后悔不了 = 坑；后悔得了但找不到入口 = 也是坑。

### C. 环境变了——索引和磁盘对不上（本轮最大的一块）

| # | 场景 | 现在的表现 | 处置 |
|---|---|---|---|
| C1 | 在资源管理器里把图**改名**了 | 重扫会按 md5/mtime 认回来（rebound），旧的标 missing | ✅ |
| C2 | 把图**挪到同目录别的位置**（子目录） | 同上 | ✅ |
| C3 | 把图**整个挪走了**，磁盘上没了 | 增量扫描标记 missing，但**以前只在仪表盘有一个数字，看不到是哪几张、也清不掉** | 🩹 |
| C4 | 想看看「索引里有、磁盘上打不开」的到底有哪些 | 新增「断链体检」页：逐条比对磁盘，列出文件名 + 完整路径 + 原目录，标注是扫描标的 missing 还是本次体检才发现的 | 🩹 |
| C5 | 文件只是被挪走，还想让它回来 | 体检页每行有「重扫目录」，扫一遍文件还在就自动对上 | 🩹 |
| C6 | 确认文件真的没了，想把死链清掉 | 「清理选中」；默认**只删索引、不留墓碑**，文件以后挪回来照样重新收录 | 🩹 |
| C7 | 就是不想再收录它 | 同页「清理并排除（不再收录）」，需输确认词「清理并排除」 | 🩹 |
| C8 | 体检之后文件又回来了，我还点了清理 | 后端清理前会当场再查一次磁盘，文件在的**跳过不删**并在提示里报「N 条文件已回来、跳过」 | 🩹 |
| C9 | 整个盘符换了 / 图库搬到别的盘 | 目前只能注销目录再按新路径登记，人工标注会跟着索引走 | ⚠️ 建议做「目录迁移」：只改 `directories.path` 前缀，不动图片行。属于改动可控的中等工程 |
| C10 | 目录暂时拔了 U 盘 / 网络盘掉线 | 目录可标「离线」，扫描会跳过并提示；但已有索引仍显示为正常。建议把离线目录下的图在列表里打个「来源离线」角标 | ⚠️ |

### D. 删除与后悔（本轮起点）

| # | 场景 | 现在的表现 | 处置 |
|---|---|---|---|
| D1 | 「只删索引」到底删了什么 | 确认框写明：源文件不动、路径登记为「仅移除索引」、增量扫描不再收录 | ✅ |
| D2 | 删错了想恢复 | 回收站页新增「已排除」标签，列出所有墓碑（文件名/路径/原目录/时间），一键**解除排除并立刻重新入库**，不用自己去点扫描 | 🩹 |
| D3 | 文件已经不在了，点了恢复 | 明确报「文件已不在原位置…可以用「移除记录」清掉这条墓碑」，不静默失败 | 🩹 |
| D4 | 只想撤销排除，不想现在入库 | 「移除记录」：只删墓碑，下次增量扫描自动重新收录 | 🩹 |
| D5 | 排除表堆了几十条想全清 | 「清空排除表」，确认词「清空排除表」 | 🩹 |
| D6 | 「删除源文件」 | 文件进 `data/trash`，回收站页可原地恢复，恢复后自动重建索引 | ✅ |
| D7 | 清空回收站 | 二次确认 + 确认词，提示「源文件是磁盘上真实副本，删了就真没了」 | ✅ |
| D8 | 删了源文件、又清了回收站 | 真没了，界面上已尽力提示 | ⚠️ 可考虑清空时保留一份 `.tar` 快照，但成本/收益待定 |

## 三、本轮实际改了什么

| 改动 | 位置 | 为什么 |
|---|---|---|
| 「删索引」可逆：排除表列表 / 恢复 / 移除记录 / 清空 | `images_repo`、`manage_svc`、`ops`、`Trash.vue` | 删除不该是终点 |
| 排除表加自增主键 | 迁移 `003_excluded_id.sql` | 墓碑要能单条定位，路径塞 URL 又长又危险 |
| 断链体检：比对磁盘 / 清理 / 重扫目录 | `manage_svc`、`ops`、`Health.vue` | 项目原来只统计了个数字，看不到是哪几张、也清不掉 |
| 清理断链默认不留墓碑 | `manage_svc.prune_broken` | 文件挪回来还得能重新收录 |
| 清空索引 / 注销目录前自动快照 | `manage_svc.snapshot_index`、`ops`、`library` | 人工标注不可再生，AI 结果才可再生 |
| 同义词 / 术语权重可删 | `catalog_repo`、`knowledge`、`Categories.vue` | 只进不出 = 写错一次永久留在检索里 |
| 侧栏加「断链体检」入口 | `settings.js`、`router.js` | 新页面得能点进去 |

统计：后端 +4 组接口（排除表 4 个 / 体检 3 个 / 同义词权重删除 2 个）、1 条迁移；
前端 +1 页面（`Health.vue`）、重写 1 页（`Trash.vue` 双标签）、改 4 处确认文案。
测试：新增 `tests/test_recovery.py` 8 条；`test_ops`/`test_search` 各补若干断言。

## 四、仍然敞开的（按建议顺序，需要爹拍板）

1. **目录迁移**：整体换盘/挪位置时，只改路径前缀就能把索引救回来。目前只能注销重登记，人工标注全丢（现在至少有快照了，但没导入功能）。
2. **快照能导回去**：现在快照只写不读。配一个「从快照恢复人工标注」的动作才算闭环。
3. **嵌入模型配错导致向量全线不可用**：这是 04 文档 D 系列就列出的老问题，还没动。
4. **图片标 failed 但已有描述**：状态机自相矛盾，界面上会出现「有描述 + 失败」。
5. **空库首次列表查询 2.1 秒**：首次冷启动体验差。
6. **每次上传都新建并登记一个 uploads 子目录**：时间久了侧栏会堆一串目录。
7. **离线目录下的图没有来源角标**。
