# picture-analysis 前端重构方案（第二轮）

> 决策时间：2026-09-29　前置文档：[`01-前端功能分析.md`](./01-前端功能分析.md)
> 已确认的三条用户决策：① 技术栈保留 **Vue3 + Vite**；② 补全「有 API 无 UI」的缺口，并允许增加体验优化；③ 视觉走 **亮色为主 + 可切暗色 + 多套主题色**。

---

## 1. 目标、边界与非目标

### 1.1 目标

1. **换得动皮肤**：所有颜色、圆角、间距、字号来自 CSS 令牌，支持亮/暗两种模式 × 6 套强调色，用户选择落盘到后端设置。
2. **消灭复制粘贴**：列表类页面的「筛选条 + 视图切换 + 多选 + 无限滚动 + 加载态 + 空态」抽成一个 `<ImageGrid>`；页面级骨架（页头 + 区块）抽成一个 `<Panel>`。
3. **补上 14 项无 UI 能力**：通知中心、日志查看器、健康状态、分类字典、自定义字段、改名、移动、目录高级策略、分用途连接探测、批量 patch、CSV 导出、存储分布、直读契约、任务事件分级。
4. **状态收敛**：设置、toast、通知、侧栏模块全部进单例 store，页面上不再出现第二次 `/api/settings` 请求。
5. **错误可见**：全站统一的错误边界 + toast，所有写操作失败时保持 UI 状态不变。

### 1.2 非目标（明确不做）

- **不改后端契约**：不新增/修改任何 REST 端点、不改 `app/` 下的业务逻辑。若确有必要，先在本文登记为「待议」。
- **不引入新的运行时依赖**：不加 Pinia、不加 Tailwind、不加 UI 组件库、不上 TypeScript。理由是本项目希望 `npm i` 后零决策即可构建，且 Vue3 的 `reactive` 已经够用。
- **不做 i18n 多语言**：schema 里有 `language` 配置项，但界面全中文，本次不引入语言包。
- **不写前端测试**：维持后端 pytest 门禁即可，前端靠构建 + 冒烟清单验收。

## 2. 技术决策

| 项 | 决策 | 理由 |
|---|---|---|
| 框架 | Vue 3.5 `<script setup>` + Composition API | 沿用现状，团队无人需要再培训 |
| 构建 | Vite 6，`build.outDir = dist` | 后端 `main.py` 已写死托管 `frontend/dist`，不能改 |
| 路由 | vue-router 4，`createWebHistory` + 路由懒加载 + `meta.title/icon` | 后端 SPA 回退已覆盖任意路径；懒加载减小首屏 |
| 状态 | 手写 `reactive` 单例模块（非 Pinia） | 全局状态只有 4 类：设置、toast、通知、 app shell UI。引入 Pinia 是过度工程 |
| 样式 | 手写 CSS，分三个文件：令牌 / 基础 / 组件 | 见 §3。不引 Tailwind 是为了让样式可以用普通 CSS 变量做多主题切换而不依赖构建期扫描 |
| 类型 | 纯 JS（JSDoc 标注关键契约） | 现状无 TS，引入 TS 会波及构建链，收益不成比例 |
| 图标 | 内联 SVG 组件（不引图标库） | 零依赖、可继承 `currentColor`、不受主题影响 |

**为什么主题切换不用 `data-theme` + 多套 `:root`？**
旧实现已经用了 `[data-theme="dark"]`，可以继续用，但强调色不能靠再复制 6 份 `:root`（组合爆炸：`模式 × 强调色`）。改为**两层变量**：

```
第 1 层（中性色，只受模式影响）   :root / [data-theme="dark"]  → --bg, --surface, --text, --line …
第 2 层（强调色，只受主题影响）   [data-accent="azure|violet|…"] → --accent, --accent-soft, --accent-contrast
其余组件只用 var(--accent)，永不见硬编码色值。
```

这样 `黑夜 + 靛蓝`、`亮色 + 琥珀` 只是 `<html data-theme data-accent>` 两个属性的组合，CSS 不需要为每个组合写一套。

### 3.3 交互约定

- **键盘**：`/` 聚焦全局搜索；抽屉内 `Esc` 关闭、`←/→` 上下张、`Ctrl+S` 保存修正；表格行 `Enter` 打开详情。
- **危险操作**：一律 `ConfirmDialog`。凡服务端要求确认词的（删源文件、清空回收站、清空索引），弹窗内置输入框并**回显后端要求的具体内容**（例如删源文件时直接告诉你「请输入文件名 IMG_0042.jpg」）。
- **加载态**：首屏 `Skeleton cards`，翻页时底部出现「加载中」而不是整屏 spinner（避免用户失去当前位置）。
- **反馈**：写操作成功/失败都出 toast；失败 toast 里直接显示后端 `error.message`（已是人话）。

## 6. 状态管理方案

四个单例模块，全部用 `reactive` + 显式 `refresh()`，不做隐式副作用：

```js
// app/settings.js
export const settings = reactive({ schema: null, values: {}, profiles: [], dirty: {}, loading: false })
export async function loadSettings()          // GET /api/settings
export function stage(key, value)             // 标脏，不立即写库
export async function commitSettings()        // PUT /api/settings，只提交 dirty，成功后合并
export const appearance = reactive({ mode, accent, density, cardSize })  // 派生自 settings.values
export function applyAppearance()             // 写 <html data-theme / data-accent / data-density>
```

- **不再有 `<router-view :settings="...">` prop 透传**，页面要用就 import 单例。
- **侧栏角标**：`jobs.pending+paused`、`proposals.pending`、`notices.unread`，统一在 App.vue 里一个 10 秒定时器里拉（原来是 5 秒拉 jobs+proposals 两个接口，现在与通知合并为一次批量并发，但请求数不变、周期放宽，减少抖动）。
- **toast 规则一致性**：只有写操作（mutation）失败才 toast 错误；轮询类拉取失败静默（避免后端没起时刷屏），但在顶栏显示一个「后端未连接」的持久标记，点一下可重试。

## 7. 性能与可靠性的具体做法

| 问题 | 做法 |
|---|---|
| 缩略图缺失容错 | 缩略图 404 / 损坏时由 `ImageCard` 本地换成占位图，而不是反复重试请求 |
| 大列表渲染 | `ImageGrid` 用 cursor 分页 + `IntersectionObserver` 哨兵触发，单页 48 张；列表视图用同样的数据源，只是渲染不同 |
| 图片解码压力 | 缩略图 `<img loading="lazy" decoding="async">` |
