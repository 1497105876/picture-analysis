# 架构设计说明（SAD）

> 回答"系统由哪些部分组成、各自职责、如何协作、为什么这样分"。
> 质量属性目标见 `quality.md`，数据与接口细节见 `design.md`，决策背景见 `docs/adr/`。

| 项 | 值 |
|---|---|
| 架构风格 | **分层 + 管道/过滤器**（扫描→提取→识图→索引→检索），策略可插拔 |
| 交付形态 | 单机单进程本地 Web（FastAPI 托管 API + 静态前端），无外部服务依赖 |
| 对外契约 | ① REST API（本机 UI 用）② SQLite 只读直读（Agent 用） |

---

## 1. 架构目标（质量属性驱动）

架构决策只为四个核心质量属性服务，优先级从高到低：

1. **可靠性/健壮性**：外部 AI 服务是不可靠依赖，必须被隔离在可失败的边界内（软失败）
2. **可维护性**：配置 schema 驱动、模块职责单一，新增配置/规则不改核心代码
3. **性能**：10 万张不卡——浏览走索引+游标分页，检索走 FTS5/向量，缩略图独立生成
4. **安全性/隐私**：进程只听 127.0.0.1、隐藏区全通路过滤、密钥只在 `.env`

> 反目标（明确不追求）：多机扩展、高并发写入、云部署——单机单用户场景下追求这些只会增加复杂度。

## 2. 架构风格

```
┌─────────────────────────────────────────────────────────────┐
│  浏览器（Vue3 SPA，构建产物静态托管）                          │
└──────────────────────────┬──────────────────────────────────┘
                           │ HTTP (127.0.0.1)
┌──────────────────────────▼──────────────────────────────────┐
│  API 层（FastAPI 路由，薄）                                   │
│  参数校验 · 错误码映射 · 静态文件托管                          │
├─────────────────────────────────────────────────────────────┤
│  应用服务层（用例编排，事务边界）                               │
│  入库 · 识图队列 · 搜索 · 管理 · 设置 · 对话 · 提案             │
├─────────────────────────────────────────────────────────────┤
│  领域层（纯逻辑，无 I/O）                                      │
│  RRF 融合 · 规则求值 · 状态机 · 限速决策 · 分类/标签模型         │
├─────────────────────────────────────────────────────────────┤
│  基础设施层（可替换的外部世界适配器）                            │
│  SQLite仓储 · FTS5/向量 · VLM/嵌入客户端 · 文件系统 · 缩略图    │
└─────────────────────────────────────────────────────────────┘
        ▲                                           ▲
        │ 只读打开（Agent 生态，不经 HTTP）            │ 后台任务线程
┌───────┴─────────┐                     ┌───────────┴──────────┐
│ SQLite 数据库文件 │                     │ 识图/扫描 Worker 队列 │
│ （对外契约）      │◄────────────────────│ 限速器 · 重试 · 记账   │
└─────────────────┘                     └──────────────────────┘
```

**两条铁律**：

- **依赖方向只向下**：API → 服务 → 领域 ← 基础设施（领域不 import 基础设施，基础设施实现领域定义的 `Protocol`）
- **一切写入经服务层**：API 不直接写库；Agent 直读连接以只读模式打开，物理上无法写入

### 2.1 为什么是"分层 + 管道"

- 分层：把"会失败的外部世界"（AI 服务、文件系统）压到最底层，上层可假定它们软失败而非崩溃——直接服务可靠性目标
- 管道：扫描→提取→识图→索引每个环节都是可暂停、可重试、可观测的阶段，天然对应识图队列状态机
- 策略可插拔：限速、OCR 触发、规则求值、检索融合都是"接口 + 默认实现"，可配置切换，满足开闭原则

## 3. 架构视图

### 3.1 模块视图（包结构与职责）

```
picture-analysis/
├── server.py               # 唯一入口：python server.py → 127.0.0.1:8321
├── app/
│   ├── main.py             # 应用装配（create_app）：路由注册、静态托管、生命周期
│   ├── api/                # API 层：每资源一个路由模块，薄到只剩参数与调用服务
│   ├── services/           # 应用服务层：用例编排、事务边界、软失败策略
│   ├── domain/             # 领域层：纯函数与实体（RRF、规则、状态机、限速决策）
│   ├── storage/            # 基础设施：SQLite 仓储、FTS5、向量、迁移
│   ├── ai/                 # 基础设施：OpenAI 兼容客户端（识图/嵌入/对话）、重试与记账
│   ├── files/              # 基础设施：扫描、哈希、EXIF、缩略图、回收站
│   └── config/             # 配置 schema 定义与加载（.env + settings 表）
├── frontend/               # Vue3 + Vite（构建产物 → app/static/）
├── tests/                  # 测试（结构见 testing.md）
├── docs/                   # 全部文档
└── scripts/                # 本地 CI 脚本、打包脚本
```

| 层 | 允许依赖 | 禁止 |
|---|---|---|
| api | services、config | 直接 import storage / 直接 SQL |
| services | domain、storage 接口、ai 接口、files 接口 | 绕过领域规则直接拼 SQL 业务逻辑 |
| domain | 无（标准库 only） | 任何 I/O、任何框架（FastAPI/SQLite） |
| storage/ai/files | domain 定义的 Protocol | 被 domain 反向 import |

> 违反上表 = 架构违规，CI 的 import-linter（或 ruff 自定义规则）负责拦截。

### 3.2 运行视图（进程内组件）

| 组件 | 线程/协程 | 职责 | 失败边界 |
|---|---|---|---|
| FastAPI/uvicorn | asyncio 主循环 | HTTP、静态文件 | 单请求异常→错误码，进程不退 |
| 扫描 Worker | 后台线程池 | 目录扫描、提取、缩略图 | 单文件失败跳过并记日志 |
| 识图 Worker | 后台线程池 + 队列 | 取任务→限速→调 VLM→按需 OCR→落库 | 服务挂→任务暂停，主流程无感 |
| 嵌入 Worker | 后台线程池 | 描述/标签变更→向量更新 | 挂→语义检索自动降级关键词 |
| watcher | 定时轮询（30s） | 监听已登记目录与剪贴板 | 关闭即无此组件 |

**所有后台组件共享一条软失败契约**：异常必须落为"状态 + 中文原因"，不得冒泡到 UI 造成全页错误。

### 3.3 场景视图（关键序列）

**A. 登记目录并入库**
`用户填路径 → 服务校验（不存在/未授权/父子重复→拒绝）→ 预估（张数/耗时/成本）→ 用户确认 → 扫描 Worker 分阶段执行（先元数据入库，后排队识图）→ 进度实时可见`

**B. 识图（含按需 OCR）**
`队列取图 → 限速器放行（20 次/分钟，间隔≥3s）→ VLM 请求 → 解析 category/description/ai_tags/elements/含文字判定 → 若含文字且未超 OCR 档位 → 追加 OCR 请求 → 落库 + tokens 记账 → 每日上限检查（触顶→暂停并提示）`

**C. 混合搜索**
`查询 →（查询增强可选，失败回退原词）→ FTS5 路 + 向量路 并行 → RRF 融合 → 叠加筛选 → cursor 分页 → 返回`

**D. Agent 直读**
`Agent 以 mode=ro 打开 .db → 查询文档化的视图（已内置隐藏区过滤 + COALESCE 人工优先）→ 得到干净结果`

### 3.4 部署视图

```
本机（Windows 10/11）
├── python server.py            # 仅监听 127.0.0.1:8321
│   ├── FastAPI（REST + 托管 frontend/dist）
│   └── 后台 workers
├── .env                        # 密钥（gitignore，设置页可读回明文）
├── data/library.db             # SQLite：元数据 + FTS5 + 向量（对外契约）
├── data/thumbs/                # 统一缩略图缓存
├── data/trash/                 # 回收站（删源文件暂存）
└── data/refs/                  # 资料库参考图（压缩存储）
```

无守护进程、无安装器、无部署：Release zip 解压 → `python server.py` → 浏览器打开。

## 4. 技术选型

| 关注点 | 选择 | 理由 | 放弃的备选 |
|---|---|---|---|
| Web 框架 | **FastAPI** | 异步、pydantic 校验天然支持 schema 驱动、OpenAPI 免费得接口文档 | Flask（弱校验）、Django（太重） |
| 存储 | **SQLite 单文件**（WAL） | 零运维、**文件即对外接口**、FTS5 内置 | Postgres（违背"文件即接口"）、MySQL |
| 全文检索 | **FTS5 + jieba 预分词** | 内置、中文友好、与主库同事务 | Elasticsearch（违背轻依赖） |
| 向量 | **BLOB(float32) + numpy 余弦** | 单机 10 万级规模足够，零额外依赖 | sqlite-vec（当前规模收益小） |
| AI 协议 | **OpenAI 兼容** | 云端/本地 Ollama/LM Studio 通吃 | 各家私有 SDK |
| 前端 | **Vue3 + Vite** | 组件化、schema 驱动渲染容易、构建产物可静态托管 | 服务端模板（交互密度不够） |
| HTTP 客户端 | httpx | 超时/重试/异步可控 | requests（无异步） |

**选型纪律**：新增第三方依赖必须在 ADR 记录"解决什么问题、为什么不用标准库/已有依赖"。

## 6. 架构守护（如何防止腐化）

1. **依赖方向**：ruff import 规则 + 分层目录约定；CI 失败即拒绝合并
2. **领域纯净**：`app/domain/` 不允许出现 sqlite/httpx/fastapi import（CI grep 拦截）
3. **对外契约**：`docs/design.md` 的直读表结构变化 = 破坏性变更，必须同步文档 + 版本号
4. **软失败**：所有外部调用必须有超时与降级路径，测试见 `testing.md` 专项
