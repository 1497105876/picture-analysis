# ADR-001：SQLite 作为唯一存储，数据库文件即对外接口

- 状态：已接受
- 日期：2026-09-28
- 决策者：库主

## 上下文

系统要同时服务两类消费者：① 本机 Web 界面（管索引、人工审核）；② 本机 Agent 生态（QClaw/openclaw/workbuddy 等，要"对外提供数据库索引"）。需求要求元数据、全文索引、向量"全部入库"，且 10 万张规模下搜索 <100ms/向量 <300ms。

## 决策

**SQLite 单文件（WAL）为唯一存储**：元数据、FTS5 全文索引、向量（BLOB float32）、任务队列、配置、审计全部入同一库；**数据库文件本身就是对外接口**——Agent 只读打开文件即可，不经 HTTP、不装插件。

## 后果

- ✅ 零运维、单文件备份、事务一致性（FTS 与主表同事务）
- ✅ "文件即接口"直接满足需求第 4 条，免去接口层的权限/部署问题
- ✅ 测试只需临时文件，CI 无需数据库服务
- ⚠️ 单写者模型：写入集中在本进程（WAL + busy_timeout 缓解）
- ⚠️ 向量检索为应用层计算，超大规模需换专业向量库（当前规模不需要）

## 替代方案（放弃）

- PostgreSQL/MySQL：违背"文件即接口"与轻依赖原则
- Elasticsearch：部署过重，违背交付形态
- 分离存储（SQLite + 本地向量文件）：破坏事务与备份原子性
