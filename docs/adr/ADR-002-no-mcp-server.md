# ADR-002：不做 MCP Server，Agent 接入只走 SQLite 只读直连

- 状态：已接受（2026-09-28 由"做 MCP"修订而来）
- 日期：2026-09-28
- 决策者：库主

## 上下文

原方案计划提供 MCP Server（HTTP SSE，14 个工具）供本机 Agent 调用。经需求评审决定：**MCP Server 不做**。Agent 接入的主诉求是"对外提供数据库索引"，而 SQLite 单文件天然就是接口（ADR-001）。

## 决策

1. 不实现任何 MCP 协议端点、工具注册、SSE 通道
2. Agent 接入 = **只读打开 SQLite 文件**（`mode=ro`），查询文档化的表与视图（`design.md` 第 2 章直读契约）
3. 只读铁律、隐藏区过滤、COALESCE 人工优先等验收要求全部在**直读契约层**实现
4. 对话页的实体/标签建议走**提案队列**（人工批准入库），作为直读之外唯一的受控写通道

## 后果

- ✅ 少一个协议栈、一个端点、一组工具的实现与测试成本
- ✅ Agent 侧零安装、零配置（拿到文件路径即用）
- ✅ 只读连接物理上无法写入，安全模型更简单
- ⚠️ 每个 Agent 需要能读 SQLite（本机 Agent 均可）
- ⚠️ 无法远程访问——与"只监听 127.0.0.1"的定位一致

## 替代方案（放弃）

- MCP Server（HTTP SSE）：维护成本高，且用户已明确取消
- 自定义 HTTP 只读 API：Agent 还要学接口，不如直接读文件
- 保留 MCP 只做搜索：范围蔓延，无明确收益
