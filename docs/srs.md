## 1. 引言

### 1.1 目的

定义"图片索引数据库 + Web 管理界面"的完整需求与验收基线，作为设计、实现、测试的唯一需求依据。改一版需求，本文档的 AC 必须重新过一遍。

### 1.2 范围

- **系统内**：目录登记与扫描入库、AI 识图（含按需 OCR）、混合检索、图库管理、人工纠错、参考资料库、规则与分类、隐藏区、文件操作、扩展工具、对话问答（含提案队列）、SQLite 只读直连规范、系统设置。
- **系统外**：本机 Agent 生态（QClaw / openclaw / workbuddy 等）——它们是**直读方**，通过只读打开 SQLite 数据库文件使用本系统的产出。
- **明确不做**：MCP Server、语音/视频/文档检索、多用户、云同步、图片编辑、桌面壳、自动目录发现。

### 1.3 术语

| 术语 | 定义 |
|---|---|
| 登记目录 | 用户手动添加、获准被扫描的根目录；**未登记目录一概不读取** |
| 索引 | 数据库中关于图片的元数据、标注与分析结果；删除索引不等于删除源文件 |
| 识图 | 调用 VLM（OpenAI 兼容协议）对单张图片生成结构化描述的过程 |
| OCR | 对"识图判定含文字"的图片追加的文字提取请求，结果写入独立 OCR 表 |
| 限速 | 识图请求的全局限流，默认 20 次/分钟（相邻请求间隔 ≥3 秒） |
| 人工修正 | 用户对 AI 产出（分类/描述/标签/备注）的手工修改，优先级最高 |
| 隐藏区 | 持久的数据状态：图片在前端、搜索、相册、直读全部不可见 |
| 隐私模式 | 临时 UI 遮罩 + 目录级"永不外发云端"策略 |
| 直读 | 本机 Agent 只读打开 SQLite 文件查询，不经 HTTP、不装插件 |
| 提案队列 | 对话中 LLM 建议的实体/标签暂存区，人工批准后才入库 |
| RRF | Reciprocal Rank Fusion，多路检索结果的融合排序算法 |

### 1.4 参考资料

- `docs/需求与功能清单.md`（需求基线）
- ISO/IEC/IEEE 29148 系统与软件工程需求工程过程
- SQLite FTS5 全文检索扩展文档

## 2. 总体描述

### 2.1 产品定位

**建一个规范化的图片索引数据库，作为本机 Agent 生态的图片记忆与检索基建。找图是能力，索引是本体。** Web 界面是管索引、做人工审核的工具，不是主角。

### 2.2 用户特征

| 用户 | 使用方式 | 关键诉求 |
|---|---|---|
| 库主（本人） | Web 界面：登记目录、看进度、审核纠错、搜索、配置 | 界面不丑、状态可见、人工说了算 |
| 本机 Agent | 只读打开 SQLite 文件 | 结果干净（隐藏区排除、人工字段优先）、字段语义稳定 |
| 识图服务 | 被动接收 OpenAI 兼容请求 | 限速 20 次/分钟、成本可控、每日上限 |

### 2.3 运行环境

- Windows 10/11，Python 3.12，Chrome/Edge
- 后端轻依赖：FastAPI / uvicorn / Pillow / httpx / jieba / numpy
- 前端：Vue3 + Vite，构建产物由后端托管
- 存储：单文件 SQLite（含 FTS5、向量），无外部数据库服务

### 2.4 约束

1. 图片文件不出本机；仅识图/嵌入时发往**用户自选**服务（选本地模型可全离线）
2. 密钥存 `.env`（gitignore），设置页明文可见可编辑，不进日志/数据库/导出物
3. 服务只监听 127.0.0.1
4. 一切写入经人工 UI；直读方（Agent）只读
5. 交付形态 = 本地运行 + Release zip，**无部署环节**

### 2.5 假设与依赖

- 假设用户会提供至少一个 OpenAI 兼容端点（云端或本地 Ollama / LM Studio）
- 假设识图服务可能不可用——系统必须软失败，不因外部依赖缺失而不可用
- 假设库规模可达 10 万张图片

## 3. 功能需求

> 编号规则：`FR-<功能域>.<序号>`，与需求清单 F1-F15 一一对应。
> 所有 FR 的验收细节见第 5 章 AC；本章只陈述"必须"。

### 3.1 FR-F1 图片入库

| 编号 | 需求陈述 | 优先级 |
|---|---|---|
| FR-F1.01 | 系统**必须**允许用户手动登记多个图片根目录；**不做任何自动发现**，未登记目录零读取 | Must |
| FR-F1.02 | 系统**必须**支持每目录递归开关、扩展名白名单、glob 排除规则 | Must |
| FR-F1.03 | 系统**必须**提供增量扫描：新文件入库、消失文件标记不删记录、mtime 变更重提取 | Must |
| FR-F1.04 | 系统**必须**将盘符不可达的目录标记为 offline，插回后一次扫描复活 | Must |
| FR-F1.05 | 系统**必须**支持目录级策略：识图开关/大模型/小模型/OCR 档/隐私（永不外发）/冻结 | Must |
| FR-F1.06 | 系统**必须**提供导入向导：先预估（张数/耗时/成本）再分阶段执行（先入库后识别） | Must |
| FR-F1.07 | 系统**必须**提取宽高/大小/mtime/EXIF 拍摄时间/主色调并生成统一缩略图 | Must |
| FR-F1.08 | 系统**必须**默认计算内容哈希 MD5：同内容共存入库、移动改名按 hash 认回原身份 | Must |

### 3.2 FR-F2 AI 识图管线

| 编号 | 需求陈述 | 优先级 |
|---|---|---|
| FR-F2.01 | 系统**必须**通过 OpenAI 兼容协议逐张产出 `category`/`description`/`ai_tags`/`elements`/文字判定，各字段可独立开关 | Must |
| FR-F2.02 | `ai_tags`（3~5 个）与人工 tags 分开存储、合并检索 | Must |
| FR-F2.03 | `elements` 元素清单**必须**尽量多、尽量全（几乎可识别的一切） | Must |
| FR-F2.04 | OCR **必须**按需触发：识图判定"图中含文字"才追加 OCR 请求，结果写入**独立 OCR 表**；无文字图零 OCR 请求；判定阈值与目录强制开关可配 | Must |
| FR-F2.05 | 后台队列**必须**支持：并发可配、失败重试上限可配、实时进度、可停止、优先级策略（新图优先/目录权重/FIFO） | Must |
| FR-F2.06 | 识图**必须**全局限速，默认 20 次/分钟（相邻请求间隔 ≥3 秒），可调；另有过夜限速可配 | Must |
| FR-F2.07 | prompt **必须**可在界面编辑、支持多模板 | Must |
| FR-F2.08 | 系统**必须**记账：每次请求 tokens、累计值界面可见、批量前预估、**每日上限触顶自动暂停** | Must |
| FR-F2.09 | 识图服务不可用时系统**必须**软失败：入库/管理/关键词搜索照常 | Must |

### 3.3 FR-F3 搜索

| 编号 | 需求陈述 | 优先级 |
|---|---|---|
| FR-F3.01 | **必须**支持 FTS5 全文（文件名/描述/标签/备注），中文分词友好 | Must |
| FR-F3.02 | **必须**支持语义向量余弦检索 | Must |
| FR-F3.03 | **必须**默认采用关键词+语义 RRF 混合模式，用户无需手动切换 | Must |
| FR-F3.04 | 筛选（分类/标签/评分/收藏/目录/时间）**必须**可与搜索叠加；分页支持跳页与 cursor 游标 | Must |
| FR-F3.05 | LLM 查询增强**必须**可开关，失败自动回退原词 | Should |
| FR-F3.06 | **必须**支持同义词组与术语加权、搜索历史可开关可清除 | Should |

### 3.4 FR-F4 图库管理

| 编号 | 需求陈述 | 优先级 |
|---|---|---|
| FR-F4.01 | **必须**支持标签多值、评分 0-5、收藏、备注 | Must |
| FR-F4.02 | **必须**提供缩略图网格 + 大图查看 + 批量打标/批量评分 | Must |

| 编号 | 需求陈述 | 优先级 |

|---|---|---|

| 编号 | 需求陈述 | 优先级 |
|---|---|---|

### 3.12 FR-F12 SQLite 直读规范

| 编号 | 需求陈述 | 优先级 |
|---|---|---|
| FR-F12.01 | 数据库文件**必须**即对外接口：本机 Agent 只读直连，不装任何东西、不起任何服务 | Must |
| FR-F12.02 | **只读铁律**：直读只查不写；一切写入经人工 UI；扫描/识别等管理操作不通过直读暴露 | Must |

| FR-F12.04 | 直读取值**必须** COALESCE 人工字段优先，与前端展示一致 | Must |
| FR-F12.05 | 表结构与字段语义**必须**与文档逐字一致，改动同步文档；随库提供查询示例 | Must |

## 4. 外部接口需求

### 4.1 用户界面

见 `需求与功能清单.md` 三章 3.1（界面效果）——表单化/卡片化控件、视觉统一、schema 驱动、状态永远可见、中文优先，为**验收底线**。

### 4.2 HTTP API

- 仅本机使用，监听 `127.0.0.1`；REST + JSON；错误响应统一结构（错误码 + 中文人话 message）
- 接口清单与字段见 `design.md` 第 3 章

### 4.3 SQLite 直读接口

见 FR-F12 与 `design.md` 第 2 章数据模型；这是 Agent 生态的**稳定契约**，破坏性变更必须升版本并同步文档。

### 4.4 AI 服务接口

- OpenAI 兼容协议：`/v1/chat/completions`（识图/增强/对话）、`/v1/embeddings`（嵌入）
- 全部端点、模型、密钥由用户配置；四用途各自绑定

## 5. 验收标准（AC 基线）

> 与 `需求与功能清单.md` 四章同源；本文档为权威版本，测试用例必须逐条覆盖（追踪矩阵见 `testing.md`）。

### 5.1 功能 AC

| 功能 | 关键 AC |
|---|---|
| F1 入库 | 加目录→增量扫描入库；**未登记目录零扫描**；拔盘标 offline 插回复活；MD5 同内容共存、移动改名认回身份；递归开关生效、父子目录不可同登记；导入向导先预估后分阶段 |
| F2 识图 | 无 Key 启动零外发且队列暂停有提示；并发/重试/优先级生效；**限速默认 20 次/分钟（实测请求间隔 ≥3 秒）**；**OCR 仅对识图判定含文字的图触发并落独立表，无文字图零 OCR 请求**；tokens 记账与预估、每日上限触顶暂停；软失败全链成立 |
| F3 搜索 | 中文关键词命中；语义"搜黄昏找到傍晚"；混合 RRF 默认；cursor 深分页无重复遗漏；同义词展开、历史开关；增强失败回退原词 |
| F4 管理 | 批量打标/评分；智能相册回放=原查询；自定义字段定义即出现、不入 FTS/向量 |
| F5 设置 | 四用途独立绑定（含跟随）；探测出延迟与能力；schema 驱动渲染、脏键保存、恢复默认、审计回滚；密钥明文可见可复制 |
| F6 纠错 | 人工修正即生效且不被覆盖；打回携带纠正说明重识别；打回计数与筛选；FTS 即时更新 |
| F7 资料库 | 实体卡+参考图；三路注入命中；注入上限生效；停用实体不注入 |
| F8 文件操作 | 默认只删索引；删源文件走回收站可找回；重命名/移动后 hash 身份与标注不变 |
| F9 浏览 | 拖拽两选导入；大图连续翻页旋转；幻灯片 Esc 退出；目录树前缀筛选；粘贴导入 |
| F10 扩展 | 仪表盘数字与手算一致；清理向导执行后组内仅剩保留项且源文件在；监听目录新图 ≤35 秒入库并按开关排队；以图搜图相似命中 |
| F11 对话 | 结构化解析出关键词+筛选并回显；回答+图片卡；空解析给引导语；服务挂（模拟开关）全链降级零调用；超字数 400；提案批准前库零变化、批准后生效 |
| F12 直读 | SQLite 只读直连可查；只读铁律（一切写入经人工 UI）；隐藏区默认过滤且无绕过；COALESCE 人工字段优先；字段语义与文档一致 |
| F13 规则 | 优先级首命中即停；试跑不落库；OCR 规则延迟复算；人工分类不被覆盖；补算幂等 |
| F14 分类 | 内置 6 类不可删改；重命名/合并级联全部图片且智能相册跟随；人工 COALESCE 优先 |
| F15 隐藏区 | 隐藏后前端/搜索/相册/直读全部不可见；恢复即回来；识别备份照常 |
