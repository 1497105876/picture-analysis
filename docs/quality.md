## 第一部分：质量属性（Quality Attributes）

> 采用场景化描述：**刺激 → 系统响应 → 可度量的验收**。度量项必须能在 `testing.md` 的用例中被自动或人工验证。

### QA-1 健壮性（Robustness）——脏输入、坏依赖、异常路径都不崩

| # | 场景（刺激） | 响应 | 度量/验收 |
|---|---|---|---|
| QA-1.1 | 识图服务返回非法 JSON / 缺字段 | 字段级降级入库，任务不重死循环 | 可解析部分入库；日志记 WARN；UI 无错误弹窗 |
| QA-1.2 | 目录路径含空格/中文/超长/不存在 | 规范化校验，中文人话拒绝 | `DIR_NOT_FOUND` 等错误码 + 中文 message |
| QA-1.3 | 图片文件损坏、EXIF 缺失、0 字节 | 单文件跳过并标记，扫描继续 | 扫描完成率 100%，坏文件入失败清单 |
| QA-1.4 | 并发写库冲突（WAL） | busy_timeout + 事务重试 | 无 `database is locked` 冒泡到用户 |
| QA-1.5 | 前端传超长/越界参数 | pydantic 校验拒绝 | 422 + 中文 message，进程不退出 |

### QA-2 可靠性（Reliability）——长时间运行不丢任务、不假死

| # | 场景（刺激） | 响应 | 度量/验收 |
|---|---|---|---|
| QA-2.1 | 进程被杀后重启 | 任务表断点续跑，`running` 复位 `pending` | 重启后队列长度与进度接得上（AC-F2） |
| QA-2.2 | 断网 | 退避重试；恢复后续跑 | 不重复计费（同一 image 不重复记 token） |
| QA-2.3 | 每日 token 上限触顶 | 全队列暂停 + 中文原因 + 次日恢复 | AC-F2：触顶暂停、恢复通知 |
| QA-2.4 | 识图服务整体不可达 | 仅识图链降级，入库/搜索/管理照常 | 软失败全链 AC（模拟开关测试） |
| QA-2.5 | 长时间空闲 | 无内存泄漏、连接池复用 | 24h 空闲 RSS 增长 < 10% |

### QA-3 性能（Performance）——10 万张规模不卡

| # | 场景 | 响应 | 度量 |
|---|---|---|---|
| QA-3.1 | 首屏加载 | 索引 + 缩略图懒加载 | P95 < 1s（10 万库） |
| QA-3.2 | 关键词搜索 | FTS5 | **< 100ms** |
| QA-3.3 | 语义搜索 | 向量分块余弦 | **< 300ms** |
| QA-3.4 | 深翻页（第 1000 页） | cursor 分页 | 无重复遗漏，耗时与页深近似无关 |
| QA-3.5 | 目录扫描 | 流水线提取 | **≥ 300 文件/秒** |
| QA-3.6 | 仪表盘 | 预聚合/索引 | P95 < 500ms |

### QA-4 安全与隐私（Security & Privacy）

| # | 场景 | 响应 | 度量 |
|---|---|---|---|
| QA-4.1 | 外部网络访问 | 仅绑定 127.0.0.1 | 非回环地址连接被拒（可测） |
| QA-4.2 | 日志/审计/导出 | 密钥脱敏 `***` | grep 密钥值零命中（CI 可测） |
| QA-4.3 | 隐藏区查询 | 物理分表 + 文档化对象过滤 | 直读契约对象零隐藏行（AC-F15/F12） |
| QA-4.4 | 路径穿越（`../../`） | 规范化 + 登记目录前缀白名单 | 越界路径 400，零读取 |
| QA-4.5 | 隐私目录外发 | 请求出口统一检查 | 隐私目录图片零外发请求（可断言 mock） |
| QA-4.6 | 危险操作 | 确认词逐字匹配 | 不匹配 400，源文件不动 |
| QA-4.7 | 密钥暴露面 | 界面明文可见（有意为之），**日志/库/导出不落** | 见 QA-4.2；威胁模型已文档化 |

### QA-5 可维护性（Maintainability）——加配置、加规则不改核心

| # | 场景 | 响应 | 度量 |
|---|---|---|---|
| QA-5.1 | 新增一个配置项 | 加一条 schema 定义 | **前端零代码**即可渲染（AC-F5） |
| QA-5.2 | 新增一类检索融合策略 | 实现 `FusionStrategy` 协议 | 不改搜索服务主体（开闭） |
| QA-5.3 | 直读表结构变更 | 迁移脚本 + 文档同步 + 版本号 | CI 校验 `design.md` 契约清单存在 |
| QA-5.4 | 层间违规依赖 | CI import 检查 | 违规即红 |

### QA-6 可测试性（Testability）——AC 全部可自动验证

| # | 场景 | 响应 | 度量 |
|---|---|---|---|
| QA-6.1 | 外部 AI 依赖 | FakeAI 适配器（可注入固定响应/延迟/故障） | 单测不碰网络 |
| QA-6.2 | 文件系统 | tmp_path 夹具 + 生成的小图片 | 无真实用户目录依赖 |

## 第二部分：设计原则（Design Principles）

> 每条原则给出**本项目的落地约束**：✅ 允许 / ❌ 禁止。CI 或 code review 负责执行。

### SOLID

| 原则 | 本项目落地 | ❌ 反例 |
|---|---|---|
| **SRP 单一职责** | 一个模块只有一个变更理由：`services/` 每服务一个用例族；`storage/` 只管持久化；限速器只管"何时放行"不发请求 | 一个 `utils.py` 里既有 SQL 又有 httpx 又有 HTML 渲染 |
| **OCP 开闭** | 策略接口化：`FusionStrategy`（RRF/加权）、`OcrTrigger`、`RatePolicy`、`Notifier`——新增策略 = 新增实现类，不改调用方 | 在搜索函数里 `if strategy == 'x'` 无限加分支 |
| **LSP 里氏替换** | 任何 `Protocol` 实现可互换（FakeAI 可替换真 AI、内存时钟替换系统时钟），行为契约（超时语义、异常类型）一致 | Fake 实现偷偷返回成功掩盖故障 |
| **ISP 接口隔离** | 接口按使用者拆分：`ImageReader`（worker 用）≠ `ImageWriter`（API 用）≠ `DirectReadView`（Agent 用） | 一个 30 方法的 `Repository` 接口强迫所有实现全实现 |
| **DIP 依赖倒置** | `domain/` 定义 `Protocol`，`storage/ai/files/` 实现；服务层构造注入 | 领域层 `import sqlite3`、业务函数内 `requests.post(...)` |

### 其他核心原则

| 原则 | 落地 |
|---|---|
| **迪米特法则** | 只与直接协作对象说话：API 层不许链式 `a.b.c().d()` 穿透三层 |
| **组合优于继承** | 队列行为用组合（`RateLimiter` + `RetryPolicy` + `Budget` 拼装），禁止继承树超过两层 |
| **单一事实源** | 配置默认值只在 schema 定义里出现一次；分类内置 6 类只在一处种子数据；文档冲突以 `srs.md` 为准 |
| **显式优于隐式** | 状态机转换必须有事件记录；配置项必须标注 `effective: immediate/on-save`；魔法数字禁止（限速默认 20 必须来自 schema default） |

## 第三部分：工程原则（Engineering Principles）

| 原则 | 本项目含义 | 检查手段 |
|---|---|---|
| **模块化** | 按 `architecture.md` 的包结构切分，模块对外只暴露服务/协议，内部自由 | 目录结构评审 + import 方向 CI |
| **关注点分离** | UI 管展示、服务管用例、领域管规则、基础设施管 I/O——同一份"限速/OCR/隐藏"逻辑**只在一处定义** | 代码评审；重复逻辑 DRY 检查 |
| **契约优先** | 先定 `srs.md` AC 与 `design.md` 契约（REST/直读），再写实现；测试断言契约而非实现细节 | 测试用例 ↔ AC 追踪矩阵 |
| **DRY** | 配置 schema、错误码表、分类字典单点定义，多处引用 | code review；grep 重复常量 |
| **YAGNI** | 明确不做清单（MCP、多用户、云同步…）里的东西**一行不写**；扩展点只在真有第二实现时抽象 | PR 审查对照 1.4 |
| **KISS** | 优先标准库与最直方案；每加一个依赖需在 ADR 说明 | ADR 记录 |
| **小步提交** | 每次提交 = 一个可描述的变更（`feat:`/`fix:`/`docs:`/`test:`/`chore:`），可回滚 | 提交信息规范（下文） |
| **一切皆代码** | 配置、规则、文档同库版本管理；`.env` 除外（密钥） | gitignore 审查 |
| **本地优先交付** | 无部署：CI 绿 = 可发布，产物是 Release zip | `delivery.md` 流水线 |

## 第四部分：编码与提交规范

### Python

- Python 3.12，类型注解**必须**（mypy strict 通过）
- 格式与 lint：**ruff**（format + lint：E/F/I/UP/B/SIM），CI 强制
- 命名：`snake_case` 函数/变量、`PascalCase` 类、`UPPER_CASE` 常量；领域概念命名与文档一致（`analysis_state`、`proposal`、`hidden`）
- 异常：定义领域异常（`RateLimited`、`AiUnavailable`…），API 层统一映射错误码；**禁止裸 `except:`**
- 日志：`logging` 结构化，禁止 `print`；密钥永不入参打印
- 注释：只解释"为什么"；代码本身能说"是什么"就不写

### 前端（Vue3）

- 组件 `PascalCase.vue`，组合式 API；schema 渲染组件集中一处
- 状态：Pinia store 按域切分；服务端状态不复制进 store
- 文案全中文；错误展示用 `message` 字段（人话），不暴露原始堆栈

### 提交信息

```
<type>: <中文描述，说清“改了什么、为什么”>
type ∈ feat | fix | docs | test | refactor | perf | chore | req
需求变更额外标注：req: 并同步 srs.md AC
```

### 分支与协作

- `main` 恒绿（CI 通过才可合并）；短分支 `feat/*`、`fix/*`，合并即删
- 提交粒度小；一个 PR 只做一件事
