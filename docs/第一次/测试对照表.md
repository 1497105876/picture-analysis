# picture-analysis 功能验收测试对照表

> **用法**：按模块逐条手工测试，每条左侧 `- [ ]` 打勾 = 通过；不符合就在文末「Bug 记录」里登记编号。
> **状态图例**：✅ 预期可通过 ｜ 🚧 部分实现（按下文"预期"测，不要当 bug）｜ ⚙️ 仅接口无界面 ｜ ❌ 未实现 ｜ 🚫 已搁置不测。
> 自动化基线：`python scripts/ci.py` 全绿 = 90 用例 / 覆盖率 87% / ruff+mypy+架构门禁+前端构建。

## 0. 环境准备

- [ ] **启动**：`start.bat`（或 `python server.py`）→ 浏览器开 `http://127.0.0.1:8321`，首页落到图库页。
- [ ] **准备测试图库**（建议建 `D:\test-pics\`）：
  - 3 个子目录（如 `相册A/`、`截图/`、`混合/`），共 20~30 张图（含中文文件名）；
  - 复制 2 张**内容相同、文件名不同**的图（测 MD5）；
  - 放 1 张**扩展名是 .jpg 但内容损坏**的文件（测坏图跳过）；
  - （可选）放 1 张 2 亿像素级**超大图**（测防崩溃，见 T1-08）；
  - 建 1 个**子目录再放几张图**（测递归开关）。
- [ ] **两种配置模式**（分开测）：
  - **模式甲（无 Key）**：不填任何 API Key → 用于测软失败、零外发；
  - **模式乙（真 Key）**：填 OpenAI 兼容 Key（云端或本地 Ollama/LM Studio）→ 用于测真实识图/检索。

## 1. F1 图片入库

- [ ] **T1-01 未登记零扫描**：启动后不登记任何目录，图库应为空、提示"没有图片"。（✅）
- [ ] **T1-02 两阶段登记**：图库 →「登记目录」→ 输入路径 → **第一步：估算** → 显示"发现 N 个文件 / MB / 预计分钟 / token / 今日剩余 / 预算内"；此时**库里仍是 0 张**。（✅）
- [ ] **T1-03 确认登记**：**第二步：确认登记** → toast"已登记并扫描完成：新增 X、更新 Y、跳过 Z"，缩略图网格出现、目录表出现该目录。（✅）
- [ ] **T1-04 重复登记不报错**：对同一目录再走一遍向导 → 估算提示"该目录已登记，确认后执行增量扫描"，按钮变"**第二步：增量扫描**"，确认后正常扫描、**不出现 409 报错**。（✅）
- [ ] **T1-05 递归开关**：向导取消"递归子目录" → 重新登记一个含子目录的库 → 子目录里的图**不入库**；勾上递归 → 子目录图入库。（✅）
- [ ] **T1-06 增量扫描**：目录表点「增量扫描」→ 新加 1 张图 → toast 显示"新增 1"；删掉 1 张原图 → 扫描后该图**标红"文件丢失"但记录还在**（总数不变）。（✅）
- [ ] **T1-07 MD5 身份**：① 同内容不同名两张 → 两张都入库（不互斥）；② 把已入库的图**改名** → 扫描 → 认回原 id（评分/备注等标注不丢）。（✅）
- [ ] **T1-08 超大图/坏图不崩**（近期修复）：坏 `.jpg` 与超大图放同目录 → 登记扫描 → **整个目录扫全**（toast 的"新增"数 = 正常图数量），坏图/超大图计入"跳过"；设置页出现通知"图片尺寸过大…"；超大图入库但状态为"**跳过（超大图/隐私）**"、不排识图任务。（✅）
- [ ] **T1-09 元数据**：打开某图详情 → 有宽高、大小、修改时间；有 EXIF 的图"拍摄时间"有值，且可用"拍摄时间"排序。（✅）
- [ ] **T1-10 白名单/排除**：设置 → G4 改 `default_extensions` 只留 `.png` → 重扫 → jpg 不再入库；配 `exclude_globs` 如 `*草稿*` → 匹配文件被排除。（✅）
- [ ] **T1-11 离线目录**：把已登记目录改名/移走 → 扫描 → 404"目录不可达"并标离线（⚙️ 界面无离线标识，看通知与接口返回）；改回原名再扫 → 恢复。（🚧 接口有）
- [ ] **T1-12 目录策略接口**：`PATCH /api/directories/{id}` 传 `{"privacy":1}` 等生效（⚙️ 界面仅"启用/停用"，用 curl 测）。

## 2. F2 AI 识图管线

- [ ] **T2-01 无 Key 软失败（模式甲）**：不填 Key 登记图库 → 入库照常、缩略图照常、**关键词搜索照常**；任务页识图任务显示"暂停"，原因含"缺少 API Key"；通知有提示。（✅）
- [ ] **T2-02 零外发**：模式甲下用抓包/日志确认没有任何出网请求（可看 `data/logs/app.log` 无 HTTP 出站记录）。（✅）
- [ ] **T2-03 真实识图（模式乙）**：填 Key → 登记后任务页出现 analyze 任务 → 逐张变"成功"，图片详情出现 **AI 分类 / AI 描述 / AI 标签 / 元素清单**。（✅）
- [ ] **T2-04 限速**：保持默认 G3（20 次/分钟、≥3 秒）→ 观察日志/抓包，相邻两次识图请求**间隔 ≥3 秒**；把 G3 调成 60 次/分、1 秒 → 间隔相应变小。（✅）
- [ ] **T2-05 每日上限**：G3 设 `daily_token_limit` 为很小值（如 1000）→ 识图跑一阵后任务自动"暂停"，原因含预算；把系统日期拨到次日（或等次日）→ 自动恢复。（✅）
- [ ] **T2-06 OCR 按需**：准备一张**纯风景无文字**图 + 一张**截图/带字**图（模式乙）→ 无文字图**不产生 OCR 请求**（日志），带字图详情里能查到 OCR 文本（独立表，直读验证：`sqlite3 "file:data/library.db?mode=ro" "SELECT image_id, text FROM ocr_results"`）。（✅）
- [ ] **T2-07 字段开关**：设置 G2 关掉"元素清单"字段 → 重新识别（详情页打回重识别）→ 结果不再产出 elements，token 消耗下降。（✅）
- [ ] **T2-08 队列操作**：任务页对运行中任务**取消**、对失败任务**重试**、"清已完成" → 状态与事件列表相应变化；失败任务有 error 文案。（✅）
- [ ] **T2-09 并发与重试**：G3 调 `vision_concurrency=3` → 日志可见并发；制造失败（错 Key）→ 自动重试至 `max_retries` 后标失败。（✅）
- [ ] **T2-10 prompt 模板**：G2 修改 `vision_prompt_override` → 打回重识别 → 新结果风格随 prompt 变（模式乙）。（✅）
- [ ] **T2-11 成本记账**：仪表盘"Token 累计"随识别增长；估算（登记向导）与实际消耗量级一致。（✅）

## 16. 配置组抽测（G1–G18）

| 组 | 抽测点 | 预期 |
|---|---|---|
| G1 | 探测延迟/能力；断开改坏 Key 再探测 | 报错用人话 |
| G3 | 限速/并发/每日上限 | 见 T2-04/05 |
| G4 | 白名单、排除、启动扫描、**watcher 全局开关** | 见 T1-10、T10-04 |
| G5 | ocr_policy=强制开/关/按需 | 关→不 OCR；强制→全 OCR |
| G6 | search_mode=混合/仅关键词/仅语义 | 切换生效（🟡 建议默认混合别动） |
| G7 | 日志级别、自动备份份数 | `data/logs/app.log`、`data/backups/` |
| G8 | 主题/强调色/缩略图尺寸/默认排序/启动页 | 即时或保存后生效 |
