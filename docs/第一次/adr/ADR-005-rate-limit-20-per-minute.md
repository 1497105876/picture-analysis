# ADR-005：识图默认限速 20 次/分钟（相邻请求 ≥3 秒）

- 状态：已接受
- 日期：2026-09-28
- 决策者：库主

## 上下文

需求："识图要有限额，默认最多一分钟 20 次，即 3 秒一次。"识图模型普遍有速率限制，超限会被封禁或排队；成本上限之外还需要**频率上限**。

## 决策

1. **全局识图限速器**：默认 `per_minute=20`、`min_interval=3.0s`，滑动窗口 + 最小间隔**双重约束**（二者同时满足才放行）
2. 所有识图/OCR 请求共享同一计数器（跨线程加锁）
3. 配置组 G3 可调（1~60/分钟），`effective: immediate`，改完立即生效
4. 被限速的任务转 `paused` 状态并记录等待秒数，UI 显示"已达每分钟 20 次上限，N 秒后继续"
5. 过夜限速在其之上叠加（更小的 per_minute）

## 后果

- ✅ 双重约束下**任意两次请求间隔 ≥3 秒**，对服务方温和且可预期
- ✅ 限速逻辑是领域层纯函数 + 可注入时钟——单测用虚拟时钟，无需真等
- ✅ 与每日 token 上限正交：一个管频率，一个管总量
- ⚠️ 大批量入库时吞吐受限（20/分钟 ≈ 1200 张/小时）——过夜限速与目录策略可权衡
- ⚠️ 改小限额不会撤销已放行请求（可接受）

## 替代方案（放弃）

- 仅并发数控制：并发 1 也可能连发（无间隔保证），不满足"3 秒一次"
- 仅令牌桶无最小间隔：短时内仍可能 1 秒 5 次
- 每目录独立限速：需求未提，且全局限额已覆盖风险；YAGNI
